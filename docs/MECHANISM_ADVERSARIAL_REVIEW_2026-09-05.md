## 判断依据

1. 单条规则应有明确的触发条件和有限的状态变化，能说明怎样执行。
2. 不同对象应能复用规则，某条规则的结果应能成为其他规则的输入。
3. 简单性需要计算被藏在参数、条件、效果或专用脚本里的复杂性。
4. 候选是否必要，要相对于一组明确的已有规则判断。
5. 比较后果时，要考虑后续行动、代价、时序和各主体获得的信息。

## 阻碍冻结的发现

### B1：把描述世界的词汇数量，当成了运行规则的复杂度

- 定位：附件第 27–46、96–114、224–305 行；特别是
  `Connection(A, B, type, strength, conditions, effects)` 和九项 kernel 清单。
- 构造反例：为每件法宝写一个专用 `effects` 程序，再把所有法宝都表示为
  “实体＋状态＋连接＋规则”。清单仍然只有九个名字，却仍有几百套互不复用的行为。
- 违反目标：单条规则简单、复杂性来自组合。用统一数据外壳容纳任意程序，不足以满足这个目标。
- 最小修正：将“实体、状态、位置”视为描述方式；另行把实际变化写成短规则。
  每个 `conditions/effects` 展开后都要计入规则清单，不能作为不计成本的万能字段。

例如，`物品 + 行为能力` 仍未交代能力怎样改变世界；
`空间布局条件 + 条件触发规则` 也尚未给出可组合的阵法规则。
这些表达可以作为设计提纲，不能单凭它们宣布专用系统已被消去。

### B2：删掉名词，不等于删掉该名词承载的行为差异

- 定位：附件第 492–544 行；研究笔记第 18–25 行。
- 构造反例：甲持有一把普通剑，乙持有一把仍被原主人绑定的剑。两人此刻都能挥剑，
  即时后果相同；稍后原主人尝试召回，结果可能不同。仅比较眼前结果会误删持续关系。
- 另一个反例：把“认主”改叫 `特殊状态_17`，再增加“若该状态存在则允许远程召回”分支。
  名词虽然消失，新语义并没有消失。
- 违反目标：用真实后果区分必要机制，而不是靠改名或者忽略未来差异完成简化。
- 最小修正：明确本次比较使用的已有规则；记录每次新增的状态、条件和分支。
  对相同初态与行动序列，比较即时及延迟结果、代价、时序和主体可知信息。
  若模型含随机性，比较相应的结果分布或声明的随机规则，而不是要求两次独立抽样逐次一致。

现有笔记已经提醒要看后续差异；仍需补充“新增字段或脚本也属于设计改动”这一点。
这只是有限案例上的等价性检查，不能证明所有未来情境都等价。

### B3：“必须产生新的行为类别”会误删有意义的约束

- 定位：附件第 319–354、451–488 行。
- 构造反例：角色仅剩一次法力供给，同一供给可以维持逃生工具，也可以发动攻击。
  使用入口没有增加，但先攻击会使逃生手段不可用。删除这个容量约束会改变可行计划。
- 违反目标：复杂性可以来自状态和组合，无需不断增加动作名称。
- 最小修正：把“新增行为类别”改成“是否改变可行行动序列、机会成本、时机或信息条件”。
  有数值不等于有价值，也不等于没有价值；本反例只说明该数值可以改变选择，未证明它好玩。

“灵气浓度”不必是独立机制，但它可以作为既有资源或环境规则的参数。
同样，疲劳、注意力、媒介消耗也可能只是另一种容量约束，不能仅靠换名字认定更有系统价值。
应比较玩家实际能改变什么、不同选择造成什么差异，以及表示这些差异的成本。

### B4：连接、身份、控制和权限的边界不足以处理违抗与欺骗

- 定位：附件第 13–21、75–114、162–189、263–276 行。
- 构造反例：弟子收到师父归还飞剑的要求；弟子实际持有飞剑，也能够选择不归还。
  若“师徒连接”被直接解释为师父拥有物理控制权，就会把可违抗的要求变成强制服从。
  若弟子只是隐瞒飞剑所在，物体位置没有改变，改变的是师父掌握的信息。
- 违反目标：不同主体行为与信息应在世界状态中产生有区别的后果，不能由一个关系标签包办。
- 最小修正：在案例里分别记录实际执行者、持有者、被承认的资格和各主体获得的信息，
  再由明确规则决定哪些关系产生哪些效果。无需据此先造完整身份或所有权系统。

同一数据结构可以存“债务”和“诅咒”，但前者是否导致追债、后者是否自动伤害，
需要不同的具体规则。关系记录的统一不构成效果语义已经统一的证明。

### B5：“获得修改规则的权限”引入了尚无结算办法的规则冲突

- 定位：附件第 116–160 行，尤其是“剑必然命中”与“规则优先级”。
- 构造反例：攻击方拥有“必然命中”，防御方拥有“必然不被命中”。
  两者同优先级时，文字没有决定结果；单纯再加优先级，也没有解决同级或相互触发的问题。
- 违反目标：组合后结果应由已定义规则决定，不能临场追加解释。
- 最小修正：首轮只允许修改明确的条件或结算参数，并针对实际发生的冲突定义处理方式。
  “可以任意修改现实法则”暂留为内容愿景；不能作为默认可调用的底层能力。

这不否认高阶能力可以产生质变。射程、作用对象、持续方式和可穿过的阻隔变化，
本身就可能改变可行计划，是否需要更高层的规则改写应另行举证。

## 非阻碍项：继续研究时需要注意

### N1：共用资源结构，不代表不同作用必须遵循同一条传播规则

- 定位：附件第 435–447 行。
- 构造反例：在一个候选世界中，水沿坡流动，声音被不同材料衰减，传授知识则复制信息，
  教授者不会因此失去原有知识。把这三者统一成“从 A 扣除、给 B 增加”会得到错误结果。
- 相关目标：共用状态和操作接口，同时保留会改变结果的差异。
- 最小修正：先固定一个具体操作的语义，再检验哪些对象可以复用。
  不必为了“通用”假定水、热量、香火和信息具有相同的输运、损耗或复制行为。

### N2：覆盖率和当前能力的判断缺少支撑材料

- 定位：附件第 114、309、516、538–546 行。
- 问题：“覆盖非常大比例”“现有系统不能表达”“至少 2–3 个独立案例”没有绑定样本和比较基线。
- 构造反例：三个情节都来自同一种设定，能触发三次同样的特殊效果，却不能解释第四个异质案例。
- 相关目标：候选需要跨实例复用，而不是以出现次数代替规则质量。
- 最小修正：把这些表述标为假设；记录支持案例、反例及实际不能复用的地方。
  少量案例可用于发现问题，不作为机制普适性或游戏性合格的证明。

## 对九项候选的处理建议

| 原候选 | 本轮建议 | 下一步最小问题 |
| --- | --- | --- |
| 实体、状态、位置 | 保留为描述世界的词汇 | 哪些字段确实改变结果，哪些只是内容标签？ |
| 资源 | 保留为待具体化的规则族 | 一次转移究竟怎样扣除、增加、溢出和损耗？ |
| 感知 | 保留为重点候选 | 作用或信息如何到达某个主体，哪些内容仍不可知？ |
| 控制 | 保留问题，暂不扩成完整系统 | 谁实际执行行动，命令是否会被执行，如何区分？ |
| 连接 | 先作为持续关系的表示方式 | 哪条明确规则读取它，又造成什么结果？ |
| 转化 | 拆成少量有具体输入输出的规则 | 转化保留、消耗或产生了哪些状态，后果如何继续参与组合？ |
| 规则 | 移出“世界元素”的计数 | 把它展开为真正需要执行的规则；任意规则改写继续待定。 |

时间推进、持续过程和历史痕迹在原长清单中出现，在九项清单中没有明确归属。
它们可以由已有表示与规则表达，但需要写出行为，不能把从名单删掉视为已经解决。

## 三个补充候选：提出，但暂不计入新机制

以下是对原方案缺少的操作语义所作的建议，不是把九个名字扩充成十二个名字。
每项都先尝试用已有规则组合表达；组合已经足够时，就保留组合而不新增 primitive。

### C1：作用的可达性

一句候选规则：**来源与目标之间存在一条可通行的路径，该类作用才可到达目标。**

最小表示：每条连接记录允许通过的作用类别；路径上的每条连接都允许该类作用通过时，
目标才可达。这条规则只判定能否到达，传递量、损耗和速度另由明确规则决定。

- 最小情境：来源与目标距离不变，仅关闭一道阻隔，某种信号便无法到达目标。
  单有坐标和距离不足以区分前后结果。
- 异质用途：可见范围、消息传递、能量供给、物体通行。能共用路径表示不意味着作用完全相同。
- 反例边界：声明只能挡住某类作用的阻隔，不应自动挡住所有类别；另有允许路径时也不能判定全局不可达。
- 消去检查：如果既有空间/流动/感知规则已经计算这种可达性，就属于已有机制；
  如果必须为每个场景补“特殊不可达”分支，才需要研究一个可复用的路径规则。

### C2：持续占用

一句候选规则：**一份容量被某过程占用期间，不能同时分配给另一个过程。**

最小变化：可用容量足够时，启动过程并扣除它占用的可用容量；不足时不能启动。
过程结束后释放占用。这里扣除的是可再次分配的容量，不是消耗品。

- 最小情境：一个供能器一次只能维持一个对象。任务结束后容量恢复；
  中途结束是否释放、耗材是否退回，需要由同一过程规则明确决定。
- 异质用途：法宝供能、持续施法、工具被借用期间的可用性。
- 反例边界：可同时服务多个对象的容量不能被强制写成一；释放占用也不等于退回已经消耗的资源。
- 消去检查：优先用“可用量/已占用量＋已有时间和结束规则”组合表达。
  如果这样已能完整表达，就不新增占用机制；新增动作按钮也不是必要条件。

### C3：结构依赖

一句候选规则：**必要支撑失效时，依赖它的持续效果也失效。**

最小变化：某个支撑状态由有效变为失效时，将依赖它的持续效果标为失效，
这个变化也可以继续影响下游依赖。首个纸面例子只考虑单向依赖；
互相支撑的闭环以及支撑恢复后的重启方式，尚未在这条候选中定义。

- 最小情境：三个连接部件共同维持通路，移除必要的中间部件后通路中断；
  部件数量和资源总量可以不变，只改变连接方式。
- 异质用途：设施的供给链、阵法部件、承载结构。每种用途应提出明确的必要依赖，不能只写“结构正确”。
- 反例边界：移除无关部件不应影响效果；存在替代支撑或缓存资源时，也不应一律立即终止。
- 消去检查：先尝试用已有关系、可达性和条件规则表达。只有剩余行为不能复用时，才讨论独立规则。

其中 C1 和 C3 可能共享表示，C2 很可能是已有资源与时间语义的组合。
本轮提供的是检验问题，没有证明三者彼此独立或缺一不可。

### 放在一起时，是否真的发生组合

构造一个最小情境：供能器通过一条通路供给护罩，护罩需要持续供能，
供能器只能同时维持一个过程。先明确这个例子没有备用通路和缓存资源。

- 切断供能通路 → 供能不可达 → 必要支撑失效 → 护罩失效。
- 供能器已被另一个过程占用 → 没有可用容量 → 护罩不能启动。
- 停止占用过程 → 容量释放；此时再次尝试启动护罩，仍须检查通路是否可达。

这条链的价值在于：可达性与占用的结果都成为持续效果的条件，
不需要为“破阵”另写一条专用规则。只是移开一块无关石头，应当不改变上述结果。
如果增加备用通路或缓存，它们必须真的参与判定，不能由叙述临时豁免失效。

这些是待实现的预期结果，尚未作为测试运行。这个例子也进一步说明，
C3 可能只是 C1/C2 结果的条件组合，未必值得单列为独立机制。

## 本轮不建议作为独立新增项的例子

- “积累到阈值后发生变化”：先检验资源/状态更新与条件触发是否足够。
- “痕迹、记忆、延迟报应”：先检验持久状态、主体信息与后续触发是否足够。
- “灵气、寿元、疲劳、MP”：先检验它们是否只是已有资源或条件模型的不同参数。

是否新增，取决于实际需要执行的行为差异；这些名称本身既不能证明必要，也不能证明无价值。

## 对思考方法的建议修订

保留用户原问题，并追加一个比较约束：

> 固定本次已有规则和可尝试的操作，去掉名词后，
> 是否仍能表达相同条件下的结果、代价、时序和主体可知信息？
> 如果需要增加专用字段、条件或脚本才能做到，就把这些增加计入设计差异，再判断是否值得。

不必一次证明整个世界。第一轮只需几组跨类型的真实材料，
以及针对它们构造的失败情境；先用部分材料提出规则，再用其余材料挑战它。
比较时允许结论为“已有组合足够”“需要新状态”“需要新规则候选”或“材料不足”。
