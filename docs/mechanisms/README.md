# 世界系统与机制研究

这里研究用户希望玄幻世界中能够发生的事情：从小说情境出发，梳理其成立因素、
可能的实现方式，再反推需要哪些可复用的底层规则。
目录保存这一过程中的材料线索、候选解释、反例和讨论结论。
当前采用六个主要系统，信息与知识归入“社交与组织”。
这是一份逐步积累的研究目录；分类的采用不代表其中的机制已经成立或实现。

## 核心目标

单条规则足够简单，通过不同状态和规则组合，能够表达很多复杂现象。
复杂性主要来自组合，而不是不断扩充机制本身。

## 从想发生的事情出发

研究主线：

**具体情境 → 成立因素 → 可能的实现方式 → 可复用的规则候选。**

智斗、艳遇、秘境等都可以作为收集方向，具体记录应落到一件值得让世界支持的事情上。
例如，智斗需要保留参与者如何利用处境和信息影响结果；艳遇可以关注相遇和互动如何使关系变化；
秘境则需要继续指明其中发生了什么探索、发现或冲突。
这些只是帮助选取情境的方向，不预先规定每类故事必需哪些因素或结局。

一件事情可以同时涉及多个系统，六个分区负责归档与关联。
我们可以先记录感兴趣的情境，再逐步补充分析；不要求先证明它属于哪个底层机制。
分析要区分材料已经写出的因素与我们推测的因素，并允许同一情境存在多种实现方案。

最终希望得到的是：少量规则为何足以支持这些事情，以及规则组合在哪些情况下会失败。
是否能运行、是否能产生有意思的选择，仍需后续原型验证。

## 怎么继续记录

先在相应分区写普通 Markdown，注明来源是小说材料、网页线索、游戏参考还是主动设计。
一篇笔记可以围绕四件事逐步展开：

- **发生什么**：一件具体的事情及其来源；保留材料实际描述的行为与后果。
- **靠什么成立**：参与者、条件和相互影响；区分已给出的因素与待确认的推测。
- **可以怎样实现**：能产生这一情境的规则组合或备选方案，不必立即选定。
- **需要哪些规则**：哪些已有组合足够，哪些存在缺口；保留候选、反例和未解决的问题。

未分析的部分可以留空；已经采用的设计选择应与尚待检验的猜想分别注明。
没有材料支撑的想法也可以记录，但须保留其设计猜想的身份。
“暂时说不清”可以留待研究；相似名称或相似结果不自动意味着同一机制。
